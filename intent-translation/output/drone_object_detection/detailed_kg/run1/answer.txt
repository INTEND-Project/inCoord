## Refined Problem Statement

You need to ensure that object detection classifications of people, generated by your drones flying in Vienna, are delivered to your dashboard in real-time and without loss. The main technical objectives are to minimize end-to-end latency, maximize throughput and reliability, and guarantee lossless transmission from drone to dashboard.

---

## 1. Decomposition of Technical Subcomponents

**A. Object Detection Service (on K3s Cluster)**
- Processing video/image streams from drones using object detection.
- Current deployment: 6 pods, throughput 30 req/s, latency 200 ms (both tunable).

**B. Network Transmission (Drone → Cluster → Dashboard)**
- Network latency is 100 ms.
- Network throughput is 4.27 MBps (tunable).

**C. Delivery to Dashboard**
- Service throughput and latency unknown, but assumed to follow similar constraints as upstream.
- Dashboard itself is not detailed, but is the consumer of classification results.

## 3. Estimated Real-Time & Lossless Delivery Requirements

### Industry/Research Benchmarks

- **Real-time latency**: <250 ms (object detection) + network time (<200 ms total preferred for interactive feel)
- **Throughput**: Should accommodate peak drone event rate (est. 30-60 req/s minimum, higher if multiple drones stream in parallel)
- **Network loss**: <0.1% packet loss (ideally 0% for lossless delivery)
- **Precision/Recall**: Out of scope for infra, but detection models (YOLO etc.) can reach >0.9 precision/recall
- **Bandwidth requirement**: For classification results (small payloads), 1-5 MBps is sufficient for many concurrent events; for images, plan for more (up to 10-20 MBps if images are sent).

## 6. Recommendations for Real-Time, Lossless Classification Delivery

### 1. **Increase Service Throughput and Lower Latency**
   - Tune the object detection service to increase throughput (e.g., adjust pod replicas, optimize resource allocation) aiming for at least 40 req/s, ideally 60+ to handle burst or multiple simultaneous drones.
   - Target sub-150 ms service latency for object detection. If possible, scale horizontally by increasing pods.

### 2. **Optimize Network Metrics**
   - Increase network throughput to at least 5 MBps (10 MBps preferred), especially if sending image frames along with classifications.
   - Reduce network latency below 80 ms if possible, through network QoS, dedicated links, or reducing hops/congestion.

### 3. **Guarantee Lossless Transmission**
   - Monitor observable metrics for packet loss (ideally <0.1%).
   - Ensure acknowledgment and retry mechanisms in the data pipeline if packet loss occurs (out of infra scope, but monitorable).

### 4. **Monitor and Adjust**
   - Continuously monitor the above metrics; adjust tunable parameters as workload or drone/event count increases.

## 7. Constraints and Assumptions

- **Assumption**: Drone video feeds are pre-processed and only object detection classifications (not raw video) are sent to dashboard.
- **Constraint**: Only tunable metrics (latency, throughput—service and network) can be adjusted at the infrastructure level.
- **Assumption**: Vienna region has stable and modern network infrastructure.
- **Constraint**: Application-level changes (e.g., detection model, dashboard logic) are not under infrastructure control.

## Summary

To achieve real-time, lossless classification delivery from your drone to the dashboard in Vienna:

- **Increase throughput** (40-60 req/s) and **reduce service latency** (100-150 ms) for object detection.
- **Boost network throughput** (≥5 MBps) and **lower network latency** (≤80 ms).
- Monitor all relevant observable metrics, especially around throughput, latency, and packet loss.
- Dynamically adjust tunable metrics as drone count or data volume increases.

These infrastructure-level adjustments ensure your system can reliably deliver timely results to your dashboard, fulfilling the requirement for real-time, lossless object detection event delivery.
