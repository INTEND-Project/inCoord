## Refined Problem Statement

The user is deploying a drone in Vienna and wants to guarantee that object detection classifications of people are delivered to a dashboard in real time without loss. This requires configuring the underlying infrastructure (network and service) to minimize end-to-end latency and prevent data loss, accounting for the drone’s local processing, network transport, and the object detection service in the cloud.

---

## 1. Breakdown of Technical Subcomponents

**A. Real-time Constraints & Data Flow**
- The drone performs object detection and sends classification results (typically lightweight JSON or message) to a remote dashboard.
- Latency from object detection output on the drone to dashboard display must be as low as possible (ideally under 300 ms for "real-time" experience).

**B. Network**
- Wireless connectivity in Vienna (assume LTE/5G is available).
- Network throughput and latency are key: need to ensure bandwidth is sufficient for burst data and latency is minimized.

**C. Cloud Service**
- The object detection service is already running with tunable Service Latency and Throughput.
- Infrastructure allows tuning of service and network metrics (Network/Service Throughput, Network/Service Latency).

---

---

## 3. Metric Dependencies

- **End-to-End Latency** = Network Latency + Service Latency
- **Throughput**: Must be greater than expected data rate from drone (usually <1 Mbps for object classification messages, but tune for bursts).

---

## 4. Constraints & Assumptions

- Drone object detection runs onboard; only classification results (not video) are sent.
- Network is LTE or better in Vienna, with urban coverage.
- Budget/cost not explicitly specified, so prioritize performance.
- Packet loss to be minimized (no loss tolerated for classification messages).

## Recommendations

- **Service Latency**: Tune object detection service to process within 120-150 ms. Lower if possible to allow for network jitter.
- **Network Latency**: Optimize routing and prioritize traffic to achieve 50-120 ms (LTE/5G urban Vienna).
- **Network Throughput**: Ensure a minimum of 5 Mbps reserved for drone traffic to handle spikes and prevent congestion.
- **Service Throughput**: Set above peak expected message rate, ideally 30-50 req/sec.
