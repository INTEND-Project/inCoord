**Requirements:**

## 3. Metric Estimation & Modeling

### Breakdown:
- **Total End-to-End Latency** = Drone transmission latency + Network Latency + Service (Processing) Latency + Delivery latency to dashboard
- **Target End-to-End Latency** (industry): **<500 ms** recommended, with sub-300 ms for high responsiveness [source: AWS, Azure IoT, NVIDIA Metropolis].
- **Network Throughput**: Needs to support classification event rate; 4.27 MBps is >30x the requirement for classifications (if each event is <10 KB, 30/s ≈ 300 KB/s).
- **Service Latency (Processing)**: Target **<100 ms** for near-instant inference (current max: 200 ms).
- **Network Latency**: Target **<100 ms** (current is exactly 100 ms).

#### Dependencies:
- End-to-end latency is the sum of network + processing + delivery.
- Throughput is only a constraint if classification frequency or payload size increases.

#### Lossless Transmission:
- With current throughput and latency, lossless delivery is feasible if network and service can handle peaks.
- Need to ensure network buffers and processing queues do not overflow.

## 4. Refinement & Synthesis (Iteration 2)

- Network throughput for event-driven detection is not a bottleneck unless streaming video.

#### Synthesis:

- **Network Latency** is at the upper bound of recommended threshold.
- **Network Throughput** is sufficient but can be increased if multi-drone or higher detection rates are anticipated.

## Recommendations

To fulfill your requirements in Vienna:

1. **Tune Service Latency:**  
   - Aim for <100 ms by allocating sufficient resources (CPU/GPU, pod scaling).  
   - Current value (200 ms) is at the upper end; reduce toward lower bound (10–50 ms) if possible.

2. **Tune Network Latency:**  
   - Ensure network path from drones to cluster is optimized.  
   - Maintain latency at or below 100 ms; strive for <80 ms where possible.

3. **Maintain Network Throughput:**  
   - 4.27 MBps is more than sufficient; monitor to ensure it remains above aggregate event rate.

4. **Monitor and Alert:**  
   - Set alerts for spikes in service/network latency or throughput drops.
