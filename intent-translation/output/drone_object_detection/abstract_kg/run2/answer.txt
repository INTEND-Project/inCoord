## Refined Problem Statement

You are flying a drone in Vienna and require that object detection classifications (specifically for people) are delivered to your dashboard in real-time, with no loss. This requires configuring the cloud continuum (network, compute, storage) supporting the drone's data uplink, object detection processing (on a K3s Kubernetes cluster, node: worker1), and result delivery to your dashboard to minimize latency and loss.

---

## 1. Technical Subcomponents

- **End-to-End Latency**: Time from object detection event (on drone/camera) to display on dashboard.  
    - Includes: network uplink (drone → cloud), processing delay (object detection service), network downlink (cloud → dashboard).
- **Service Throughput**: Number of object detection classifications processed and transmitted per second.
- **Network Latency & Throughput**: Affects real-time delivery and loss. 
- **Reliability (Packet Loss)**: Data loss must be minimized (target: 0% for classifications).

---

| Service Throughput         | 10-30 inferences/sec      | System state: 30 cur.|

**Dependencies:**
- E2E Latency = Network Uplink Latency + Service (Processing) Latency + Network Downlink Latency
- Packet Loss inversely related to network quality and buffer/queue management.

## 6. Recommendations (Cloud Infrastructure)

- **Tunable Configuration Targets:**
    - Set Service Latency on K3s node to ≤100 ms.
    - Ensure Service Throughput is ≥ expected detection rate (e.g., 30/sec).
    - Configure Network Latency budgets so that E2E latency is < 150 ms.
    - Allocate sufficient Network Throughput (≥2 Mbps for detection metadata, higher if images are sent).
- **Monitoring:** Continuously monitor packet loss; implement auto-scaling for throughput spikes.
- **Validation:** Test end-to-end with actual drone to ensure real-world latency and loss targets are met.
