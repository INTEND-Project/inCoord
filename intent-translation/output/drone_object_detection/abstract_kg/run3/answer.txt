## Refined Problem Statement

You require that object detection classifications (specifically, detections of people) generated by drones flying in Vienna are reliably transmitted in real time to your dashboard, with minimal latency and without data loss.

---

## 1. Plan Decomposition

**Main technical subcomponents:**

- Network performance (latency, throughput, packet loss)
- Service performance (object detection processing latency and throughput)
- End-to-end real-time constraint (from drone capture to dashboard visualization)
- Reliability (ensuring classification results are not lost in transit)

---

## 2. Information Gathering & Research Synthesis

**Relevant Findings:**

- Real-time object detection from drones typically targets a frame rate between 10–40 FPS, commonly around 24 FPS ([VATE Edge-Cloud System, Vienna](https://dsg.tuwien.ac.at/team/snastic/publications/ICFEC__Maresch_VATE_Object_Detection.pdf)).
- Processing (inference) times for edge devices like Nvidia Jetson TX2 are commonly 50–200 ms per frame ([Super accurate low latency object detection on a surveillance UAV](https://www.mva-org.jp/Proceedings/2019/papers/06-02.pdf)).
- The acceptable end-to-end latency for real-time surveillance and analytics (from capture to dashboard) is generally considered <= 200 ms.
- Network bandwidth for transmitting classification results (not raw video) is relatively low, but *network reliability and latency* are critical.
- Packet or message loss must be minimized (ideally zero at the application layer, possibly via acknowledgments or reliable protocols).

**Observable Metrics from System State:**
- Service Throughput (tunable): 10–200 req/s (current: 30 req/s)
- Service Latency (tunable): 10–200 ms (current: 200 ms)
- Network Latency (tunable): 100 ms
- Network Throughput (tunable): 4.27 MBps

---

## 3. Metric Estimation & Modeling

### a) End-to-End Latency

- **Target:** ≤ 200 ms total (including network + inference)
  - Service Latency: 10–200 ms (recommend ≤ 50 ms for better real-time performance)
  - Network Latency: Current 100 ms (industry best practice: ≤ 100 ms for low-latency streaming)
  - Dashboard/UI Rendering Latency: Typically negligible if using efficient protocols

### b) Throughput

- **Object detection result rate:** Should match or exceed the frame rate (target ≥ 24 req/s for 24 FPS, current is 30 req/s, so sufficient)
- **Network Throughput:** 4.27 MBps (well above requirements for sending only classification results, even for multi-drone)

### c) Data Loss

- **Loss Tolerance:** Zero loss for classification messages (use reliable transport protocols, but not tunable at infrastructure level—ensure network is not a bottleneck)

### d) Dependencies

- **Network Latency** impacts the minimum possible service latency.
- **Service Throughput** must not bottleneck the incoming detection event rate from drones.
- **Network Throughput** must accommodate peak event bursts (currently sufficient).

---

## 4. Constraints and Assumptions

- Drones send only classification results (not raw video) to the cluster.
- Vienna network infrastructure is assumed to be stable, but urban wireless congestion may occasionally raise latency.
- The Kubernetes cluster is within the same city or region—WAN latency is not dominant.

## 7. Recommendations (Supported by Metrics)

- **Set Service Throughput** to at least 30 req/s (preferably matching max drone FPS: 24–40 req/s, but up to 120 req/s for burst tolerance).
- **Set Service Latency** as low as feasible (target: 10–50 ms).
- **Maintain Network Latency** at ≤ 100 ms (current is acceptable, but minimize jitter).
- **Network Throughput** is already sufficient; monitor for spikes if more drones are added.

---

**Summary:**  
To ensure real-time, lossless transmission of object detection results from drones over Vienna to your dashboard, configure the tunable metrics as follows:  
- Service Latency: 10–50 ms  
- Service Throughput: ≥ 30 req/s (ideally ≥ 24 req/s per drone)  
- Network Latency: ≤ 100 ms  
- Network Throughput: ≥ 1 MBps (current is 4.27 MBps, which is sufficient)  

This configuration supports drone-generated detection results at real-time rates, keeps end-to-end latency under 200 ms, and leverages all tunable infrastructure controls available for your cluster.
